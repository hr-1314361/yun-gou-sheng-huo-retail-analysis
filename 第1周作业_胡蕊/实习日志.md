## 2026年10月26日（周一）

**今日工作内容：**

1. 搭建本地大数据开发环境：安装并启动 Docker Desktop（WSL2 后端）。
2. 编写 `docker-compose.yml`，编排三个容器：MySQL 8.0（Hive 元数据库）、Hive Metastore（端口9083）、HiveServer2（端口10000/10002）。
3. 首次启动时遇到 3306 端口冲突（本机已安装 MySQL80 服务占用），将容器端口映射改为 `3307:3306` 后成功启动，`docker ps` 确认三容器状态均为 Up。

**遇到的问题与解决：**
- 问题：`docker compose up -d` 报 "bind: Only one usage of each socket address"，3306 端口被本地 MySQL 服务占用。
- 解决：不改本机服务，将 compose 中 MySQL 映射改为 3307:3306，Hive 通过容器内部网络（服务名 mysql:3306）连接元数据库，不受影响。

**今日收获：** 掌握了 docker-compose 多容器编排的基本写法，理解了容器间通过服务名通信的机制。

## 2026年10月27日（周二）

**今日工作内容：**

1. 使用 beeline 连接 HiveServer2（`jdbc:hive2://localhost:10000`），连接成功。
2. 创建数仓 ODS 层数据库 `ydsh_ods`，按数据字典设计并创建 6 张 ODS 表：`ods_user`、`ods_product`、`ods_store`、`ods_order`、`ods_order_item`、`ods_user_behavior`。
3. 建表要点：TEXTFILE 存储格式、逗号分隔（`FIELDS TERMINATED BY ','`）、`skip.header.line.count=1` 跳过 CSV 表头。
4. 将 6 个 CSV 数据文件复制进容器，通过 `LOAD DATA LOCAL INPATH` 加载数据。
5. 数据加载过程中发现所有表行数翻倍（如 ods_order 应为15600行，实际31200行），排查发现是重复执行 LOAD DATA 未先清理所致。

**遇到的问题与解决：**
- 问题：重复加载数据导致行数翻倍，唯一性检查出现大量虚假重复。
- 解决：对所有表执行 `TRUNCATE TABLE` 后重新加载，最终验证行数与数据字典一致：1000 / 600 / 60 / 15600 / 37549 / 60000。

**今日收获：** 理解了 LOAD DATA 是追加而非覆盖语义，数据入库前先 TRUNCATE 是必要操作习惯；掌握了 Hive 外部表与分隔符配置。

## 2026年10月28日（周三）

**今日工作内容：**

1. 编写数据质量五维度评估 SQL：完整性（空值统计）、唯一性（主键重复）、一致性（外键孤儿记录）、有效性（取值范围）、准确性（业务逻辑校验）。
2. 完整性检查结果：ods_user 中 gender 空值84条、age 空值51条、member_level 空值14条、email 空值193条（共1000行）。
3. 一致性检查：订单→用户、订单→门店、订单明细→订单、订单明细→商品、行为→用户共5条外键关系，孤儿记录均为0，关联完整。
4. 有效性检查：`pay_amount<0` 310条、`discount_amount<0` 769条、`quantity≤0` 718条、`unit_price<0` 798条、`price<0` 20条、年龄越界12条。
5. 准确性检查：3599条订单日期早于用户注册日期、324条折扣金额大于实付金额。

**遇到的问题与解决：**
- 问题：多条统计 SQL 用 UNION ALL 合并执行时报 "Counters limit exceeded: Too many counters: 121 max=120"（Tez 引擎计数器上限）。
- 解决：将一致性检查拆分为5个独立 SQL 文件分别执行，全部通过。

**今日收获：** 熟悉了数据质量五维度评估方法；了解到 Hive on Tez 对单作业计数器数量有限制，复杂多表 UNION 需拆分执行。

## 2026年10月29日（周四）

**今日工作内容：**

1. 缺失值处理：创建 `dwd_user` 表，age 用**均值**填充（保留4位小数），email 空值统一标记为 `unknown@`；创建 `dwd_product` 表，launch_date 缺失的11条补默认值。处理后验证三字段空值均为0。
2. 重复值处理：检测出 `ods_order.order_id` 重复600条；使用 `ROW_NUMBER() OVER(PARTITION BY order_id ORDER BY order_date, order_time)` 窗口函数保留每组第一条，通过 `INSERT OVERWRITE` 输出 `dwd_order`，行数 15600 → 15000；order_item 无重复（37549条保持不变）。
3. 处理过程中踩坑：CSV 中"空值"实际是空字符串而非 NULL，COALESCE 不生效，改用 `CASE WHEN col='' THEN ...` 修复；INSERT 时 SELECT * 会带上 rn 排序列导致列数不匹配，改为显式列出字段名。

**今日收获：** 掌握了 COALESCE 与 CASE WHEN 两种空值处理方式、窗口函数去重的标准写法；理解了 Hive 不支持 UPDATE/DELETE，清洗需通过 INSERT OVERWRITE 生成新表。
