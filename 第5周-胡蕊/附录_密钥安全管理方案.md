# 密钥与敏感信息安全管理方案

> 适用范围：云购生活数仓项目全部代码、配置与部署脚本
> 涉及密钥：大模型 API Key、MySQL 密码、Superset 密钥、ClickHouse 密码、Hive 连接凭据

## 一、风险识别

| # | 风险 | 典型表现 | 后果 |
|---|---|---|---|
| 1 | 硬编码密钥 | `api_key = "sk-xxxx"` 写进 `.py` | 代码外泄即密钥泄露 |
| 2 | 误提交 `.env` | `.env` 未加入 `.gitignore` | Git 历史永久留存明文密码 |
| 3 | 权限过大 | 应用使用 MySQL `root` 账号 | 被注入后可删库 |
| 4 | 长期不轮换 | Key 使用超过一年 | 泄露后无法及时止损 |
| 5 | 日志打印密钥 | `print(os.environ)` | 日志平台/截图泄露 |
| 6 | 前端暴露配置 | 大屏 JS 内写死 API Key | 任何人可查看源码 |

## 二、管理规范（六条）

1. **集中存放**：所有敏感信息只存在于 `.env`，代码通过 `os.getenv()` 读取；
2. **模板分离**：仓库只提交 `.env.example`（占位值），`.env` 永久排除；
3. **环境注入**：Docker 部署通过 `environment` / `env_file` 注入，镜像内不含明文；
4. **权限最小化**：分析类应用只给 `SELECT`，不同服务使用不同账号；
5. **定期轮换**：API Key 90 天、数据库密码 180 天轮换一次，人员变动立即轮换；
6. **最小暴露**：密钥不出现在日志、截图、前端代码与答辩 PPT 中。

## 三、密钥清单与存放位置

| 密钥 | 用途 | 存放位置 | 使用方 | 权限 | 轮换周期 |
|---|---|---|---|---|---|
| `DEEPSEEK_API_KEY` | NL2SQL 调用大模型 | `streamlit/.env`、`docker/.env` | Streamlit App | 仅推理 | 90 天 |
| `MYSQL_ROOT_PASSWORD` | MySQL 管理密码 | `docker/.env` | Hive Metastore、Superset | 建库/读写 | 180 天 |
| `SUPERSET_SECRET_KEY` | Flask 会话签名 | `docker/.env` | Superset | 签名 | 180 天 |
| `SUPERSET_ADMIN_PASSWORD` | Superset 管理员 | `docker/.env` | Superset | 管理员 | 90 天 |
| `CLICKHOUSE_PASSWORD` | ClickHouse default | `docker/.env` | Superset/压测 | 读写 | 180 天 |
| Hive 连接 | HiveServer2 | `streamlit/.env` | Streamlit App | 只读（NOSASL 内网） | — |

> 生产环境建议进一步替换为 Vault / KMS / Docker Secrets，
> 本次实训在单机环境使用 `.env` + 环境变量注入已满足安全基线。

## 四、落地实现（本仓库证据）

| 措施 | 文件 | 说明 |
|---|---|---|
| 密钥模板 | `docker/.env.example`、`streamlit/.env.example` | 仅占位值，可提交 |
| 排除环境文件 | `.gitignore` | `.env`、`*.env`、`secrets.toml` 全部忽略 |
| 代码读取 | `streamlit/nl2sql_engine.py` | `os.getenv("DEEPSEEK_API_KEY")`，无默认明文 |
| 配置注入 | `docker/docker-compose.yml` | `${MYSQL_ROOT_PASSWORD}` 等变量占位 |
| Hive 密码变量替换 | `docker/hive/conf/hive-site.xml` | `${env.MYSQL_ROOT_PASSWORD}` |
| 只读账号 | `docker/mysql/init/01_init.sql` | `ydsh_reader` 仅 `SELECT ydsh_ads.*` |
| 前端零密钥 | `echarts/` | 大屏仅静态数据，不含任何密钥 |
| 敏感信息回显 | `streamlit/app.py` | 仅显示「已连接/未配置」，不打印值 |

## 五、密钥生成与轮换

生成强随机值：

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

轮换流程：

```
① 在服务商控制台创建新 Key（保留旧 Key 有效）
② 更新 .env / 部署平台环境变量
③ 重启相关服务：docker compose up -d --force-recreate streamlit python-app
④ 验证新 Key 可用后，在控制台禁用并删除旧 Key
⑤ 记录轮换时间到《密钥台账》
```

## 六、泄露应急处置

1. **立即吊销**：控制台禁用泄露 Key（优先于任何清理动作）；
2. **轮换替换**：按上节流程生成并部署新 Key；
3. **评估影响**：查询 API 调用日志、数据库慢查询与登录日志；
4. **清理历史**：若已提交 Git，使用 `git filter-repo` 清理历史并强制推送，
   同时通知所有协作者重新克隆（历史提交中的密钥视为永久泄露）；
5. **复盘**：补充检查项，避免同类问题再次发生。

## 七、日常自查命令

```bash
# 1) 检查代码中是否出现疑似密钥
git grep -n -E "(sk-[A-Za-z0-9]{20,}|password\s*=\s*['\"][^'\"]{6,})" -- "*.py" "*.yml" "*.xml"

# 2) 确认 .env 未被跟踪
git ls-files | findstr /I ".env"

# 3) 确认 .env.example 中无真实值
findstr /I "change_me sk-your" .env.example

# 4) 检查 Git 历史中是否曾提交 .env
git log --all --name-only --pretty=format: | findstr /I ".env"
```
