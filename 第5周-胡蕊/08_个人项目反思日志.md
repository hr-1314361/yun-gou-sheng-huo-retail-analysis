## 一、项目概述

本项目历时 5 周，完成了云购生活新零售企业从原始数据接入到经营分析可视化的全流程建设。涉及数据仓库四层建模、五类脏数据清洗、GMV 时间序列预测、NL2SQL 智能问答、Superset/ECharts/Streamlit 三套可视化方案、Docker 一键部署与 Hive 查询优化。

## 二、技术收获

### 2.1 数据仓库建设

- **分层建模**：深刻理解了 ODS → DWD → DWS → ADS 四层架构的设计思想。ODS 保持原始数据不变，DWD 做清洗与明细，DWS 做轻度汇总，ADS 面向应用场景。每一层职责清晰，避免了「一层到底」的混乱。
- **分区与分桶**：掌握了按日期分区、按维度分桶的设计，以及分区裁剪、分桶 Map Join 对查询性能的提升。
- **数据倾斜治理**：理解了热点 Key 导致的数据倾斜问题，学会用 `skewindata` 与加盐（Salting）打散。

### 2.2 数据质量

- 系统性地实践了五类脏数据（缺失、重复、异常、格式、枚举）的检测与修复，认识到数据质量是数仓的生命线——下游指标的准确性完全依赖 DWD 层的清洗质量。
- 学会了用 `ROW_NUMBER()` 去重、`COALESCE`/均值填充、`CASE WHEN` 截断异常值、`regexp_replace` 统一格式、`CASE WHEN LOWER()` 统一枚举。

### 2.3 预测建模

- 掌握了时间序列预测的完整流程：趋势分解、移动平均、特征工程（滞后特征、滚动统计、周期编码）、模型对比评估、递归预测。
- 学会了批判性地看待模型结果——线性回归在本项目中优于 XGBoost，说明并非越复杂的模型越好，需根据数据特征选择合适的算法。

### 2.4 AI 集成

- 掌握了 NL2SQL 的核心要素：Schema 抽取、Prompt 设计（含 Schema 约束与示例）、SQL 安全校验（仅允许 SELECT）、执行与结果展示。
- 学会了三级降级设计（llm+hive / llm+demo / demo），保证在大模型或 Hive 不可用时系统仍可演示。
- 理解了密钥安全管理的重要性——所有 API Key 通过 `.env` 注入，禁止硬编码。

### 2.5 可视化

- 掌握了 Superset 从数据源、数据集到仪表板与筛选器联动的完整配置链路。
- 学会了 ECharts 大屏的等比缩放方案（`transform: scale`），以及跨图联动的实现思路（三维数据立方体 + 筛选状态聚合）。
- 理解了 ECharts 配置越界会静默失败（如双 Y 轴只给 1 个 yAxis），必须用浏览器实际验证而非「看代码像对的」。
- 掌握了 Streamlit 对话式应用的开发，包括 `st.chat_message`、`st.session_state`、`st.components.v1.html` 嵌入 ECharts，以及 iframe 内图表尺寸的 ResizeObserver 处理。

### 2.6 工程化部署

- 掌握了 Docker Compose 的健康检查（`healthcheck`）、服务启动顺序（`depends_on: condition: service_healthy`）、密钥环境变量注入。
- 学会了 Hive 镜像内注入 MySQL JDBC 驱动的方法。

## 三、问题与教训

| 问题 | 教训 |
|---|---|
| Superset 元数据库 URI 用 `mysql://` 但镜像只有 pymysql | 配置必须与实际环境依赖一致，不能想当然 |
| ECharts CDN 下载失败 | 关键资源应本地化，避免依赖外部 CDN |
| Streamlit 图表空白（双 Y 轴越界） | ECharts 静默失败，必须用浏览器实测 |
| Streamlit `PermissionError`（空路径指向目录） | 对环境变量空值要做防御性判断 |
| 省份份额合计 110.7% 导致地图 GMV 与全量不一致 | 数据生成时要做归一化校验 |
| Docker Desktop 未运行无法真实部署 | 环境准备要提前，配置校验不能替代真实部署 |

通过本项目，我完整实践了企业级数据分析的全流程，从数据接入、清洗、建模、分析到可视化与部署，形成了端到端的工程能力。最大的收获是建立了「数据质量是根基、分层建模是骨架、可视化是出口、工程化部署是保障」的系统化思维。同时也认识到自己在实时计算、数据治理等方向还有提升空间，将在后续学习中持续补强。
