## 一、业务背景

云购生活是一家覆盖线上（APP、小程序、PC 官网）与线下门店的新零售企业，经营 9 大商品品类（运动户外、家用电器、食品生鲜、美妆个护、服饰鞋包、数码 3C、母婴玩具、家居家装、图书文娱），业务遍及全国 20 个省份。随着业务规模扩大，企业面临以下痛点：

1. **数据分散**：订单、用户、商品、门店、支付数据散落在不同业务系统，口径不一致，难以支撑经营决策；
2. **指标滞后**：经营报表依赖人工 Excel 汇总，T+1 才能出数，无法实时发现异常；
3. **分析门槛高**：业务人员不会写 SQL，取数依赖数据团队，响应慢；
4. **缺乏预测**：无法提前预判 GMV 走势与库存需求，促销备货盲目。

因此需要建设一套端到端的企业级数据仓库与经营分析可视化系统，实现从原始数据到智能洞察的闭环。

## 二、需求分析

### 2.1 功能性需求

| 编号 | 需求 | 说明 |
|---|---|---|
| F-01 | 原始数据接入 | 支持订单、用户、商品、门店、支付等 CSV 原始数据批量导入 Hive ODS 层 |
| F-02 | 数据清洗 | 对缺失值、重复值、异常值、格式不一致、枚举不规范五类脏数据进行清洗，输出 DWD 明细层 |
| F-03 | 数仓分层建模 | 按 ODS → DWD → DWS → ADS 四层建模，支持分区、分桶、增量刷新 |
| F-04 | 指标计算 | 计算 GMV、订单量、客单价、复购率、品类占比、区域分布、时段热力等核心指标 |
| F-05 | 预测建模 | 基于历史 GMV 时间序列，构建预测模型，输出未来 7 天 GMV 预测 |
| F-06 | NL2SQL 智能问答 | 业务人员用自然语言提问，系统自动生成 SQL 并执行，返回表格与图表 |
| F-07 | 经营驾驶舱 | 基于 Superset 构建交互式仪表板，支持多图表联动与筛选 |
| F-08 | 数据大屏 | 基于 ECharts 构建 1920×1080 经营大屏，支持跨图联动筛选 |
| F-09 | 对话式分析 | 基于 Streamlit 构建对话式问答界面，嵌入 ECharts 图表 |
| F-10 | 一键部署 | 使用 Docker Compose 编排 Hive、MySQL、ClickHouse、Superset、Python App，支持一键启动 |
| F-11 | 密钥安全 | 所有密钥通过 .env 环境变量注入，禁止硬编码 |

### 2.2 非功能性需求

| 编号 | 需求 | 指标 |
|---|---|---|
| N-01 | 性能 | 单条 NL2SQL 查询响应 < 3 秒（Hive 命中分区时） |
| N-02 | 并发 | 压测 5 并发 QPS ≥ 1000，成功率 100% |
| N-03 | 可用性 | 系统可通过 `docker compose up -d` 一键部署，服务健康检查通过 |
| N-04 | 安全性 | 密钥不硬编码，SQL 仅允许 SELECT，最小权限账号 |
| N-05 | 可维护性 | 文档完整，代码模块化，Git 提交遵循约定式提交规范 |

## 三、指标体系定义

### 3.1 核心经营指标

| 指标名称 | 英文 | 计算口径 | 数据来源 |
|---|---|---|---|
| 成交总额 | GMV | SUM(订单实付金额) | ads_sales_daily |
| 订单量 | Order Count | COUNT(DISTINCT order_id) | ads_sales_daily |
| 下单用户数 | User Count | COUNT(DISTINCT user_id) | ads_sales_daily |
| 客单价 | AOV | GMV / 订单量 | ads_sales_daily |
| 人均消费 | ARPU | GMV / 下单用户数 | ads_sales_daily |
| 复购率 | Repurchase Rate | 复购用户数 / 下单用户数 | ads_repurchase_daily |
| GMV 同比 | GMV YoY | (本期 GMV - 去年同期 GMV) / 去年同期 GMV | ads_sales_daily |
| GMV 环比 | GMV MoM | (本期 GMV - 上期 GMV) / 上期 GMV | ads_sales_daily |

### 3.2 品类分析指标

| 指标名称 | 计算口径 | 数据来源 |
|---|---|---|
| 品类 GMV | SUM(amount) GROUP BY category | ads_category_topn |
| 品类 GMV 占比 | 品类 GMV / 总 GMV | ads_category_topn |
| 品类排名 | RANK() OVER (ORDER BY 品类 GMV DESC) | ads_category_topn |
| 品类客单价 | 品类 GMV / 品类订单量 | ads_category_topn |

### 3.3 区域分析指标

| 指标名称 | 计算口径 | 数据来源 |
|---|---|---|
| 省份 GMV | SUM(amount) GROUP BY province | ads_region_sales |
| 省份订单量 | COUNT(DISTINCT order_id) | ads_region_sales |
| 省份 GMV 占比 | 省份 GMV / 总 GMV | ads_region_sales |
| 门店数 | COUNT(DISTINCT store_id) | ads_region_sales |

### 3.4 时段分析指标

| 指标名称 | 计算口径 | 数据来源 |
|---|---|---|
| 时段 GMV | SUM(amount) GROUP BY hour_bucket | 热力图数据 |
| 时段品类 GMV | SUM(amount) GROUP BY hour_bucket, category | 热力图数据 |

## 四、用户角色与使用场景

| 角色 | 使用场景 |
|---|---|
| 企业高管 | 通过经营驾驶舱查看核心 KPI、区域分布、品类排名，辅助战略决策 |
| 运营经理 | 使用 NL2SQL 问答，快速查询「广东省上月销售额」「Top5 品类」等问题 |
| 数据分析师 | 基于数仓各层进行深度分析与预测建模 |
| IT 运维 | 通过 Docker Compose 一键部署与监控系统健康状态 |

## 五、验收标准

1. 原始 CSV → ODS → DWD → DWS → ADS 全链路跑通，各层行数与指标值一致；
2. 五类脏数据清洗率 ≥ 95%；
3. NL2SQL 对 6 个示例问题能正确生成 SQL 并返回结果；
4. Superset 仪表板包含 ≥ 5 个图表且支持筛选联动；
5. ECharts 大屏五类图表完整，支持跨图联动；
6. `docker compose config` 校验通过，服务可按依赖顺序启动；
7. 密钥全部通过 .env 注入，代码中无硬编码密钥。
