## 二、分层设计

### 2.1 ODS 贴源层

- **定位**：原始数据落地层，与业务系统数据结构保持一致，不做清洗转换
- **命名规范**：`ods_<业务表名>`
- **分区策略**：按 `dt`（日期）分区，支持每日增量加载
- **存储格式**：TEXTFILE（原始 CSV 格式）

| 表名 | 说明 | 关键字段 |
|---|---|---|
| ods_order | 订单原始数据 | order_id, user_id, amount, pay_type, channel, create_time |
| ods_user | 用户原始数据 | user_id, phone, gender, age, city, register_time |
| ods_product | 商品原始数据 | product_id, category, price, brand |
| ods_store | 门店原始数据 | store_id, store_name, province, city |
| ods_pay | 支付原始数据 | pay_id, order_id, pay_type, pay_time, amount |

### 2.2 DWD 明细层

- **定位**：清洗后的明细事实层，是数仓的核心层
- **命名规范**：`dwd_<主题>_<粒度>`
- **分区策略**：按 `dt` 分区
- **存储格式**：PARQUET（列式压缩）

**清洗规则**：
- 缺失值：均值/中位数填充或标记 `unknown`
- 重复值：`ROW_NUMBER()` 去重
- 异常值：截断到合理区间
- 格式：时间、手机号、金额统一格式
- 枚举：支付方式、渠道、状态统一标准枚举

| 表名 | 说明 | 粒度 |
|---|---|---|
| dwd_order | 订单明细 | 1 行 = 1 个订单 |
| dwd_user | 用户维度 | 1 行 = 1 个用户 |
| dwd_product | 商品维度 | 1 行 = 1 个商品 |
| dwd_store | 门店维度 | 1 行 = 1 个门店 |
| dwd_pay | 支付明细 | 1 行 = 1 笔支付 |

### 2.3 DWS 汇总层

- **定位**：面向主题的轻度汇总层，按 时间 × 维度 汇总核心度量
- **命名规范**：`dws_<主题>_<粒度>`
- **分区策略**：日粒度表按 `dt` 分区，周/月表全量重算

| 表名 | 主题 | 粒度 | 核心度量 |
|---|---|---|---|
| dws_sales_1d | 销售 | 天 | gmv, order_cnt, user_cnt, aov |
| dws_sales_category_1d | 销售-品类 | 天×品类 | gmv, order_cnt, gmv_share |
| dws_sales_store_1d | 销售-门店 | 天×门店 | gmv, order_cnt, aov |
| dws_sales_channel_1d | 销售-渠道 | 天×渠道 | gmv, order_cnt, gmv_share |
| dws_sales_1w | 销售 | 周 | gmv, order_cnt, aov |
| dws_sales_1m | 销售 | 月 | gmv, order_cnt, aov, mom_gmv |
| dws_user_consume_1d | 用户消费 | 天×用户 | order_cnt, gmv |

### 2.4 ADS 应用层

- **定位**：面向具体业务场景的结果表，直接对接报表/看板/API
- **命名规范**：`ads_<业务场景>`
- **存储格式**：PARQUET

| 表名 | 场景 | 核心度量 |
|---|---|---|
| ads_sales_daily | 销售日报 | gmv, order_cnt, aov, gmv_yoy, gmv_mom |
| ads_category_topn | 品类 TopN | category, gmv, gmv_share, rank_no |
| ads_region_sales | 区域分布 | province, gmv, order_cnt, store_cnt |
| ads_pay_type_daily | 支付方式 | pay_type, gmv, gmv_share |
| ads_core_kpi | 核心 KPI | gmv, order_cnt, aov, repurchase_rate |
| ads_repurchase_daily | 复购率 | repurchase_rate |
| ads_user_value_segment | 用户价值分层 | rfm_label |

## 四、分区与分桶策略

### 4.1 分区

- ODS/DWD/DWS 日粒度表按 `dt`（yyyy-MM-dd）分区，支持按天增量刷新
- 分区裁剪：查询时带 `WHERE dt = '2024-11-01'` 可避免全表扫描

### 4.2 分桶

- `dws_sales_category_1d` 按 `category` 分 9 桶，加速品类维度的 Map Join
- 分桶表支持 `SET hive.optimize.bucketmapjoin = true`

### 4.3 数据倾斜治理

- 对热点 Key（如「运动户外」品类）开启 `hive.groupby.skewindata=true`
- 对倾斜严重的 Key 采用加盐（Salting）打散

## 五、ETL 流程

```
原始 CSV
    │  LOAD DATA
    ▼
ODS 层（按 dt 分区）
    │  清洗（缺失/重复/异常/格式/枚举）
    ▼
DWD 层（明细事实，Parquet）
    │  轻度汇总（SUM/COUNT/DISTINCT）
    ▼
DWS 层（按 时间×维度 汇总）
    │  业务指标计算（占比/排名/同比/环比）
    ▼
ADS 层（应用结果表）
    │  对接 BI / 大屏 / API
    ▼
Superset / ECharts / Streamlit
```

## 六、数仓规范

1. **命名规范**：`<层>_<主题>_<粒度>`，全小写，下划线分隔
2. **字段命名**：业务含义清晰，如 `order_cnt`、`gmv_share`
3. **注释规范**：每个表、字段均有 COMMENT 说明
4. **存储规范**：ODS 用 TEXTFILE，DWD/DWS/ADS 用 PARQUET
5. **分区规范**：日粒度表必须按 `dt` 分区
6. **权限规范**：业务账号只读，ETL 账号读写
